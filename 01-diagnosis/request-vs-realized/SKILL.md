# 请求 vs 实际

## 框架
- 请求：Δz = −η ∇_z L（直接改表征 z 的"理想函数步"）
- 普通梯度：Δθ = Jᵀ Δz，实际 Δz_real ≈ K Δz，K = J Jᵀ（NTK，偏向强模式）
- Gauss-Newton：Δθ = Jᵀ(K + λI)⁻¹ Δz = (G + λI)⁻¹ Jᵀ Δz（push-through 恒等式）

## 冻结单步对照（从同一检查点、同一批、同范数）
| 臂 | 回答 |
|---|---|
| 理想函数步（直接改 z） | 损失给的方向本身对不对 |
| Adam / Adam 去动量 / SGD | 更新器是否把请求转到了强轴 |
| GN（完整 CG，仅诊断） | 参数化能否兑现（上界） |
| 结构化写入（如 R 对 W_V 线性 → W_V 左乘） | 便宜的可执行路径 |

## 判读
- 函数步改善、GN 改善、Adam 不改善 → **更新器问题**
- GN 也不改善 → **共享参数零空间**（参数化表达不了）
- 只在求谱的池内改善、跨时间块不改善 → **估计噪声**
- 函数步就不改善 → **损失本身**

## 坑
- 单步测量要选对时间点（坍塌可能发生在早期能量增长期，后期测不到）。
- 全局低秩 GGN 近似可能完全抓不住批特异的请求（G 尾部重）。
- 按批计算的请求可能互相矛盾，共享函数只能实现平均。
- 留出验证：TRAIN 上解出的步在时间分开的 VAL 上是否仍有效。
